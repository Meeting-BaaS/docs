This open-source API demonstrates the capabilities of [MeetingBaas](https://meetingbaas.com) 🐟's video meeting APIs by integrating with [Pipecat](https://github.com/pipecat-ai/pipecat)'s Python framework for building voice and multimodal conversational agents. One request sends a bot that joins the call, listens, and talks back:

```bash
curl -X POST https://speaking.meetingbaas.com/bots \
  -H "Content-Type: application/json" \
  -H "x-meeting-baas-api-key: your-api-key" \
  -d '{
    "meeting_url": "https://meet.google.com/abc-defg-hij",
    "bot_name": "Vibe",
    "prompt": "You are Vibe, an upbeat engineer. Keep turns to 2-3 sentences.",
    "entry_message": "Hey everyone, Vibe here. Let us get into it."
  }'
```

Our implementation creates AI meeting agents that can join and participate in Google Meet, Zoom and Microsoft Teams meetings with distinct personalities and context, defined either per request (`prompt`) or as reusable personas in Markdown files.

It extends Pipecat's [WebSocket server implementation](https://github.com/pipecat-ai/pipecat/tree/main/examples/websocket-server) to create:

- Meeting agents that join Google Meet, Zoom or Microsoft Teams through the [MeetingBaas API](https://meetingbaas.com)
- Customizable personas with unique context
- Several bots in the same call, with floor control so they take turns
- Per-bot choice of LLM provider (OpenAI, Anthropic, Z.ai), model, speaking speed and turn-taking sensitivity
- External context (`prompt_data_sources`) and MCP tool servers (`mcp`) per bot

## API Access

The hosted API is available at [speaking.meetingbaas.com](https://speaking.meetingbaas.com) (production) and [speaking.pre-prod-meetingbaas.com](https://speaking.pre-prod-meetingbaas.com) (pre-production, tracks the `preprod` branch). The OpenAPI specification is served live at [speaking.meetingbaas.com/openapi.json](https://speaking.meetingbaas.com/openapi.json), with an interactive Swagger UI at [speaking.meetingbaas.com/docs](https://speaking.meetingbaas.com/docs).

Every request except `/`, `/health`, `/ready`, `/docs`, `/openapi.json` and `/webhook` must carry your MeetingBaas API key in the `x-meeting-baas-api-key` header. The bot is created on your MeetingBaas account with that key, so it shows up in your dashboard and consumes your recording time like any other bot.

The API follows a minimalist design with sensible defaults while offering optional customization. A bot can be deployed with just a meeting URL, but the [`POST /bots`](/docs/speaking-bots/reference/bots/join_meeting_bots_post) body accepts parameters for tailoring behavior:

- `bot_name`, `bot_image` and `entry_message` for how the bot appears and what it says once admitted
- `prompt` for an ad-hoc persona, or `personas` to pick from the bundled persona library
- `llm_provider`, `llm_model` and `speech_speed`
- `turn_config` for Voice Activity Detection tuning (how eagerly the bot takes the floor)
- `prompt_data_sources` and `prompt_data_token_limit` to feed documents or URLs into the system prompt
- `mcp` to connect the bot to MCP tool servers, and `enable_tools` for the built-in weather/time tools

Remove a bot with [`DELETE /bots/{bot_id}`](/docs/speaking-bots/reference/bots/leave_bot_bots__bot_id__delete). Its status and recording are available through the regular [MeetingBaas API](/docs/api-v2) under the same `bot_id`.

The API includes infrastructure not visible in the route list: a bidirectional audio WebSocket per bot (`/ws/{client_id}`), one Pipecat pipeline process per bot, and a floor-control layer so several bots in one call do not talk over each other.

The API and implementation are open source. We welcome contributions and pull requests from the community. See our [getting started guide](/docs/speaking-bots/getting-started/set-up) for local development setup.
